# AeroVault SPI bring-up — step 1: spidev loopback on the Pi 5

**Date:** 2026-09-15 · **Agent:** LIMA · **Target:** `aeronode` (192.168.0.99), Raspberry Pi 5
Model B Rev 1.1, kernel `6.18.39+rpt-rpi-2712` · **Script:** `spidev-loopback.py`

Scope, from Peter: *"simple aerovault test using pi 5 spi with mosi on gpio10 — spidev loopback
test first, then we'll wire the part."* This file covers the loopback only. No AeroVault part is
connected and none is characterised here.

## What the bus looks like before anything is touched `[measured]`

```
 9: a0  pn | lo // GPIO9  = SPI0_MISO
10: a0  pn | lo // GPIO10 = SPI0_MOSI
11: a0  pn | lo // GPIO11 = SPI0_SCLK
 7: no  pu | -- // GPIO7  = none
 8: no  pu | -- // GPIO8  = none
```

- `dtparam=spi=on` **and** `dtoverlay=spi0-0cs` are already in `/boot/firmware/config.txt`.
  GPIO9/10/11 are muxed to ALT0; **GPIO7 and GPIO8 are NOT claimed** — `spi0-0cs` means the
  controller drives **no chip select at all**. Harmless for a loopback. It is not harmless for a
  real part (see Open, item 1).
- `/dev/spidev0.0` and `/dev/spidev10.0` both exist. User `node` is in group `spi`, so no `sudo`.
- `python3-spidev` present: `/usr/lib/python3/dist-packages/spidev.cpython-313-aarch64-linux-gnu.so`.

## The controller is DesignWare, not BCM — and that changes the test `[measured]`

| bus | compatible | driver | max speed | SPI_LOOP |
|---|---|---|---|---|
| `spi0` (GPIO7-11, the header) | `snps,dw-apb-ssi` @ `1f00050000` | `dw_spi_mmio` | 125 MHz | **accepted** |
| `spi10` | `brcm,bcm2835-spi` | `spi-bcm2835` | 20 MHz | **rejected, `EINVAL`** |

On Pi 5 the header SPI lives in RP1 and is a Synopsys DesignWare SSI, which implements the
shift-register loop (`SPI_LOOP`, `SPI_CTRLR0.SRL`). The BCM controller on the same machine refuses
the same ioctl — that contrast is the negative control proving the acceptance is real and not the
driver quietly swallowing a mode bit.

## Results

**Negative control — no jumper, no `SPI_LOOP`.** `--expect open` → **PASS**. All-zero at
100 kHz, 1, 5, 10, 25 and 50 MHz across every pattern (zeros, ones, AA/55, walking-one, 256-byte
ramp, 4096-byte random). An unwired bus returns nothing, so the test can tell wired from open.

**Positive control — `SPI_LOOP`, still no jumper.** `--internal-loop --expect wired` → **PASS**.
Byte-identical echo at all six clocks, including the 4096-byte transfer that exercises the DMA
path. Exit 0.

```
      0.1 MHz  ECHO       every byte returned identical
      1.0 MHz  ECHO       every byte returned identical
      5.0 MHz  ECHO       every byte returned identical
     10.0 MHz  ECHO       every byte returned identical
     25.0 MHz  ECHO       every byte returned identical
     50.0 MHz  ECHO       every byte returned identical
```

## What this does and does not prove

**Proved:** the whole software path — `spidev` character device, the `SPI_IOC_MESSAGE` ioctl,
8-bit words, mode 0, clock programming to 50 MHz, and 4 kB transfers — works on this Pi, end to
end, with byte-exact fidelity.

**NOT proved: the pins.** `SPI_LOOP` turns the data round *inside the controller*. It never
reaches GPIO10, so it cannot fail if the mux is wrong, a header pin is dead, or a flex lead is
open. A green internal loop with a broken MOSI pin looks exactly like a green internal loop —
which is the failure mode this repo keeps getting bitten by. **The wired run is still required**
and is the one that speaks to the AeroVault wiring.

## Open

1. **`spi0-0cs` gives the AeroVault no chip select.** Before the part goes on: either
   `dtoverlay=spi0-1cs` (CE0 back on GPIO8) or a `cs-gpios` pin. A part that never sees CS
   asserted will look like a dead part. Decide with the AeroVault's wiring in front of us.
2. **Wired loopback not yet run** — needs a jumper from header **pin 19 (GPIO10, MOSI)** to
   **pin 21 (GPIO9, MISO)**. Peter fits it; I run
   `python3 spidev-loopback.py --expect wired` and append the result here.
3. `[gap]` **Nothing about the AeroVault itself is known to me** — no part number, no datasheet,
   no register map, no idea of its SPI mode or clock ceiling. "AeroVault" exists in this repo only
   as a block caption in `kicad/aeronode-lite-audio/*/aeronode-audio-interface.kicad_sch`
   (*thin PCB and flex interface / flat flex*). That is the next thing I need.
