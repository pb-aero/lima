## The part is not there `[measured]`

```
JEDEC ID (9Fh + dummy) : 00 00 00   expected EF AA 21
```

Then the discriminating test — enable the Pi's internal pull-up on MISO (GPIO9) and read again:

```
JEDEC ID (9Fh + dummy) : FF FF FF
```

**MISO is undriven.** A powered W25N01GV with CS asserted would drive that line during the ID read
and return `EF AA 21` regardless of the pull-up; instead the line simply follows whatever the Pi
does with it — 0x00 floating, 0xFF pulled up. So: the click board is **not connected, not powered,
or its DO line is open.** Pull-up restored to `pn` afterwards.

**Control, so this is a finding and not a broken instrument:** the same bus, same session, same
`spidev0.0` — `SPI_LOOP` internal loopback still echoes byte-clean to 50 MHz. The controller, the
driver, the ioctl path and the CS are all working. Only the part is missing.

## Next

Nothing further can be measured until the board answers. Peter to check, in this order:

1. **3V3 and GND to the click board** — 25 mA active, and the Flash 5 Click is a 3.3 V part.
2. **DO → GPIO9 (pin 21)** — this is the line proven to be open.
3. DI → GPIO10 (pin 19), SCK → GPIO11 (pin 23), CS → GPIO8 (**pin 24**).

Then `python3 /tmp/w25n01gv-probe.py` — read-only, writes nothing, expects `EF AA 21` and dumps
SR-1/2/3 (which also tells us whether the silicon is the `IG` or the `IT`).

**The `jedec,spi-nand` overlay is deliberately NOT installed yet.** Installing it removes
`spidev0.0`, and that is the only tool for diagnosing a part that will not answer. It goes in after
the probe passes, not before.

## Then UBIFS, once it enumerates

```
cat /proc/mtd                                  # expect one 128 MiB mtd0
sudo flash_erase /dev/mtd0 0 0                 # NB: erases the part
sudo ubiformat /dev/mtd0                       # writes UBI headers, preserves bad-block info
sudo ubiattach -m 0                            # -> /dev/ubi0
sudo ubimkvol /dev/ubi0 -N aerovault -m        # -m = maximum size
sudo mount -t ubifs ubi0:aerovault /mnt/aerovault
```
`[assumed]` — that sequence is the standard one and has NOT been run here. Every line of it is
destructive to the flash, so none of it runs until the part identifies itself and Peter says go.
