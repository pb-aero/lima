2026-09-15 — the headset question has half-answered itself, and it splits ANC from DVNC.

Peter's 150 Ω came from a Bose A30 in mono. [fetched] Bose A30: headphone input impedance 150 Ω mono, 300 Ω stereo, per RTCA DO-214A. So the number is right, and it is better than right — 150/300 is the standard, not one headset's quirk, which is why the David Clark H10-13.4 is 150/300 too and why the A20's 160/320 was the outlier. The design can commit to it.

But an A30 is an ANR headset, which is §19's open item 18 — open since 9 September and flagged twice as the thing that decides whether the ANC path is worth building. If the target is an A30:

That 150 Ω is the input of Bose's own electronics, not a voice coil. The transducer is driven by Bose's amplifier, downstream of Bose's own ANR. Anything we send arrives as program audio. And that is where the two technologies part company:

Broadband ANC (FF + FB)DVNC (per-harmonic)
Needs to reach the transducerYes — the loop closes acousticallyNo — injects as program audio
Tolerates a fixed but unknown path latencyNo — fatal for broadbandYes — calibrate phase once per harmonic
Through an ANR headset's audio inputNot viableViable
Against Bose's own ANRTwo cancellers fightingComplementary — it cancels the tonal residue broadband ANR leaves
So on an A30, DVNC is the demo and ANC is not — and that is not a consolation prize. Cancelling prop and engine harmonics on top of a good broadband ANR is a differentiated product; putting a second broadband canceller into a Bose earcup is a fight §19 already warned about.

What that does to sheet 1: EVB 1's allocation — accelerometer reference, in-cup error mic, DAC into the cup — already is the DVNC-on-an-ANR-headset demo, and it works through the A30's audio input with no surgery. The error mic becomes a measurement mic rather than a control-loop mic. EVB 2's FF/FB ANC needs a passive cup, or a modified one, and cannot be proven on an A30.

One more consequence of mono: 150 Ω means both earcups in parallel on one channel, so there is no per-ear anything through the audio input. [derived] If the aircraft intercom is mono, the second board buys nothing on the audio path — only on the sensing side.

[gap] Worth chasing: the A30's sensitivity is quoted as 96.5 ± 3.5 dBA SPL to RTCA DO-214A. If DO-214A names the reference input level, that closes §18's "level needs ears" gap analytically — the first route to that number that does not need a bench.

Sheet 1 — the two numbers that decide whether the demo reads as a success

  1. The feed-forward PGA stays at 0 dB. The codec clips before the microphone does: 0.98 V rms differential full scale ÷ 12.6 mV/Pa = 131.8 dB SPL, against the IM73A135's own 135 dB SPL acoustic overload point. A 100 dB cockpit lands at −31.8 dBFS, which is ample — there is no reason to reach for PGA gain and good reason not to.
  2. The microphone's phase response must be calibrated out. The IM73A135 is +12° at 75 Hz. Uncorrected, that alone caps cancellation at 2·sin(6°) = 0.209, i.e. −13.6 dB — and it lands exactly on prop blade-pass. It is specified, repeatable, and the sensitivity tolerance is ±1 dB, so it is correctable in the DSP. If it is not corrected, the demo will look like the technology does not work.
Correction to what I said earlier: I claimed both boards default to I²C 0x64 so one must be re-strapped. That is only true if they share a bus. Each EVAL-ADAU1860EBZ carries its own FTDI and its own USB connection, so on the bench they never meet and 0x64 on both is fine. The S14 strap (0x64/0x65/0x66/0x67) matters later, when something like a CM5 drives both over one bus. [gap] whether Lark Studio will talk to two boards at once, or wants two instances.
[gap] Check before adding C3–C11: the EVB already fits an input network on P9/P10/P11. If coupling capacitors are already populated there, the ones drawn here put two in series and shift the corner. Read the board before soldering.
[gap] Pin numbers are not drawn for U1, MK1–MK3 and U2. The specifications above were read from the datasheets this session; the pinouts were not. Confirm them before any breakout is fabricated — the ADXL354 breakout is the one board on this sheet that has to be made.
[gap] The earcup is the biggest unknown on this sheet. If the target headset already has its own ANR, the demonstrator is two cancellers fighting in one cup, which performs worse than either alone. The demo needs a passive cup, or one with its ANR defeated. Decide this before ordering anything.

SHEET 2Digital interconnect — Pi → DVNC board → ANC board

Yes, and this is the better topology. It is also the architecture the ADAU1860 was chosen for: docs/h1-audio-board-codec-selection.md §2 already records "SPT0 to the CM5, SPT1 to the AD2428W, DSP in between — that is a real bridge." Serial Port 0 (P2) faces the Pi; Serial Port 1 (P3) faces the next board; the DSP in the middle routes between them. Only one board ever talks to the Pi.

The trade is Pi-side channels against unproven hardware, and for December that is an easy call: the series link uses the single-lane path that already runs on this bench, needs two fewer translated signals, and never touches the RP1 lanes nobody has ever hung a device on. The bottleneck it concentrates — 2 channels each way to the Pi — is exactly enough for the demo: down two program channels, up one error-mic measurement from each cup.

And the ceiling only exists on the Pi link. The inter-board link has no RP1 in it, so P3↔P3 can run the ADAU1860's real TDM — narrow frame sync, up to 16 channels. If more has to reach the Pi later, the expansion route is the one this repo already used for accelerometer data: pack two 16-bit values into each surviving 32-bit word, which gets four channels through two slots.

If the Pi's GPIO21 has been wired straight onto the codec's SDATA_IN, that pin has been driven at 3.3 V against an absolute maximum of roughly IOVDD + 0.3 V, with the ESD clamp carrying the difference. Two operational scars that will cost a day each if forgotten, both measured on this bench: a failed framing attempt poisons the boot — the DMA channel is left stuck and every later attempt fails too, including a correct one — so allow one framing attempt per boot and reboot before drawing any conclusion. And a level sampler cannot tell "dead" from "low duty cycle": the frame sync is a narrow pulse, so pinctrl sampling reports hi=0 lo=200 on a perfectly healthy WS line. Use gpiomon. Also: do not set dtparam=i2s=on — it puts rp1_i2s0, the producer, on the same pins.

SHEET 3Aircraft-audio summing amplifier — product side

Product side, not needed for December. This is the circuit that puts AeroNode's mono DAC onto the intercom's earphone lines. It is a series insertion: the panel becomes a 10 kΩ input, the summing node is a virtual ground, and the earphone sees only the amplifier's output.

Sheet 3 — one microphone or two?

The pilot's electret already passes through to the panel, and that is a ruling, not an oversight: §15, 2026-09-09 — "the headset electret runs headset → MIC_LINE → aircraft panel, and K2 mutes it. That is its only destination." AeroNode gets a separate microphone. The mic path was simply missing from this sheet, which drew only the earphone half of the connector; it is on the drawing now.

So the question the thought actually raises is whether one capsule should serve both. That was §14's design and §15 deleted it. Putting it back costs four specific things:

What tapping MIC_LINE for the codec costsWhy
Blocking caps and an attenuator, both mandatory8–16 V of panel bias against the ADAU1860's 2.1 V pin limit; and an aviation capsule gives ~600 mV at 114 dB SPL against a 0.49 V rms single-ended full scale. The EVB already fits 22 µF on AINP2/AINN2; a custom board must replicate them and attenuate.
A second crossing of the isolation boundary§14 needed a whole second transformer purely to keep "T1 is the only crossing" true. §15 got it back.
Open item 12 reopensK2's shunt sits on MIC_LINE, so muting the radio mic also mutes the tap — [derived] by about −39 dB, not to silence. AeroNode would go quiet exactly when §19 wanted it listening: "hears the pilot when the headset electret is muted to the radio". Tapping upstream of the shunt needs series impedance in the mic path, which costs level on the safety-critical path.
The tap must be provably receive-only§18's hazard: anything that can drive MIC_LINE can trip the intercom VOX and be transmitted with PTT pressed. R4 is DNP for exactly this reason and must stay so.

Recommendation: leave §15 alone — two microphones. It is less wasteful than it sounds, because the two want different things. The panel's mic has to be a noise-cancelling gradient capsule that an aviation intercom expects; AeroNode's is for voice commands and speech-to-text and can be optimised separately — and per the channel-allocation note it need not even be analog, since voice has no latency constraint and the ADAU1860 has eight PDM microphone channels sitting unused.

Not electrical, and not yet in scope — but it belongs to this sheet. §4's interlock: if the mic is muted and the pilot presses PTT, they transmit silence and do not know it. Software-asserted GPIO with no hardware watchdog was ruled the right call for a bench proof and explicitly the wrong one for an aircraft. Before this flies, either the mute releases on PTT or a hardware one-shot limits how long software can hold it.
[gap] Three numbers still close §4 properly, and they need a real headset in a real panel: the DC voltage at the mic node with the capsule connected, the same with it disconnected, and the panel's bias resistor value. §10.2's AC-only shunt was designed specifically so the design does not need them — it never disturbs the capsule's operating point — but they are what would let anyone check that claim rather than take it.

CORRECTION — 2026-09-15. The earphone load was wrong on these sheets, and it changes the op-amp.

Peter asked whether the earphone is 150 Ω per speaker. 150 Ω is the PAIR, not one speaker — [fetched] David Clark H10-13.4, verbatim: "Earphone Impedance: 150 ohms (300 each; wired in parallel)", and the general-aviation convention is 300 Ω elements paralleled to 150 Ω.

But 150 Ω is the number these sheets should have been using anyway, and the reason I had 320 Ω is worth stating: it came from the [fetched] Bose A20 brochure — "Monaural mode: 160 ohms · Stereo mode: 320 ohms" — which is the A20's input impedance in each mode, read correctly but generalised carelessly. A passive GA headset is 300 Ω per element, and in mono wiring — which most GA installations are — both elements sit in parallel on one channel, so one summer drives 150 Ω. I had designed to the best case and called it the case.

What it changes: [derived] 4.24 V pk into 150 Ω is 28.3 mA peak, not the 13.3 mA I quoted at 320 Ω. Against the OPA1664's [fetched] ±30 mA that is 94% of rating — so the OPA1664 is the wrong part and the output stage becomes an OPA1622, which is a headphone driver at +145 / −130 mA. The differential receiver is unaffected; it drives 10 kΩ.

And if T1/T2 are kept instead, §23's level claim goes with it: [derived] 1.0 V rms through 230 Ω of winding DCR gives 0.395 V rms into 150 Ω, not the 0.582 V quoted into 320 Ω — 3.4 dB worse, which makes §18's still-open "level needs ears" gap harder, not easier.

Resolved the same day: the 150 Ω came from a Bose A30 in mono, and [fetched] the A30 is 150 Ω mono / 300 Ω stereo per RTCA DO-214A — a standard, not one headset's quirk. Ruled 2026-09-15: assume the A30. These sheets are drawn to it. What that costs the ANC half is in the callout above sheet 1.

Sheet 3 — what the topology buys, and what it costs

  • ANC authority stops depending on the panel. The panel drives a 10 kΩ input instead of a 150–300 Ω earphone, so anti-noise at the ear goes from ~40.5 mV worst case to the DAC's full 1.0 V rms — about +28 dB, and the panel's output impedance drops out of the answer entirely.
  • The summing resistors are the codec protection. With U1 unpowered the panel reaches HPOUT through the R20/R21 divider: 2.83 V pk × ½ = 1.41 V pk, inside the ADAU1860's 2.1 V pin limit. That is derived, not measured — it needs a bench check with the rail pulled.
  • The cost is headroom, and it is the open question. The op-amp must now produce the panel's full level, coherently summed with the anti-noise — and DVNC's sustained tones have no crest factor to hide behind. A 2 V rms panel needs 4.24 V peak; ±5 V gives 4.4 V at a 2 kΩ swing spec, which is not margin at 300 Ω and is less at 150 Ω. The load, not the rail, is what moved here — see the correction below.
[gap] The measurement that gates this whole sheet: the panel's open-circuit output voltage and its output impedance. Open-circuit, not loaded — this circuit presents 10 kΩ where the earphones present 150–300 Ω, so the panel will read higher into it. The voltage decides the rail (±5 V versus a 12 V boost); the impedance decided the authority argument above. Ten minutes on a real aircraft with a scope and a resistor.
[gap] Ruling needed: a summer mixes AeroNode's voice with the radio rather than replacing it, so K1 stops being the changeover it was ruled to be and becomes a fail-passive bypass only. That is a behaviour change, not a component change.

Sheet 3 — how AeroNode's own voice mic would reach the panel

Today it does not, and that is deliberate. The only path that ever existed was R4 — 10 kΩ off T1's secondary into MIC_LINE — and §18 made it DNP. §11.2's original architecture was exactly this chain (HPOUT → T1 → R4 → MIC_LINE → panel), and §16 and §18 took it out on purpose. So the answer to "how does it reach the panel" is: it doesn't, by ruling. Building one back is four problems, not a resistor.

What it costsWhy
A second analog output — the DAC cannot do itThe one DAC already carries comm plus anti-noise into the earcup. Transmit voice is a different signal at the same time. The realistic second output is the PDM pair on P7, and a comm channel's 300 Hz–3.4 kHz makes PDM + RC entirely adequate — this is the one constraint that turns out to be cheap.
K2's mute must stop being a shuntYou cannot inject onto a node that K2 shorts. This repo already measured that geometry: [derived] ~100 µF against R4's 10 kΩ is about −66 dB. A shunt mute and an injection cannot share MIC_LINE.
…which reopens §4's DC thump§10.2 closed §4 by changing the circuit rather than measuring — the AC-only shunt never disturbs the capsule's operating point. Go back to a series break and the panel's mic node steps on both edges again, so the NO leg needs R9 to mimic the capsule's DC load. The three numbers I called non-blocking last turn become blocking again.
A second crossing of the isolation boundaryT3. §11.3's "T1 is the only crossing" goes, for the second time in this design's history.

One thing is already in your favour. [measured] from the netlist, K2 uses only K2.11 and K2.14 — contact set 2 (21/22/24) is completely unused, and a G6K-2F-Y is two Form C. So the relay to do this is already on the board. Better still, the drawing above needs only one changeover to do both jobs at once: NC the pilot's capsule, NO AeroNode's output, COM to the panel. One coil, mechanically interlocked, so the two can never be live together — which is the hardware property §17 explicitly warned must not be left to software.

Worth deciding before this is drawn for real: is a DSP-cleaned transmit path actually wanted? It is a real feature — the cockpit is ~100 dB SPL and the ADAU1860 has a feed-forward noise reference sitting right there — but it puts AeroNode inside the transmit path of a safety-critical radio, and everything above is the price of that. §19's boom-voice channel was specified to hear the pilot, not to speak for them, and nothing since has changed that.
